# v0.9.7 LINE session security
Set server-only Vercel LINE_SESSION_KEY to 64 hexadecimal characters from a cryptographically random 32-byte key (generate locally: openssl rand -hex 32). Never use NEXT_PUBLIC_, commit, or share the key. Redeploy after configuration. Without key, manual input continues working, but sending requires updated Firestore rules. Encrypted HttpOnly SameSite Strict cookie scoped to LINE endpoint, account UID authenticated on every request, 8h expiration, maximum sealed length 3800. Clear before shared-device use; browser cookie is not permanent cross-device storage, one saved session per browser. Key rotation invalidates existing sessions. Rate limit uses create-only Firestore documents per UID per fixed 30-second bucket, not a sliding window. Near bucket boundaries two sends may occur close together; failed sends consume slot. Slot documents accumulate and consume Spark quota; administrator maintenance needed, no automatic deletion. No LINE credentials in Firestore. No automated reports or student name delivery; manual authorized messages only. Test real LINE delivery, expired cookies, account switches and throttling in staging. Do not claim production ready without these tests. Publish rules after CI and merge.
